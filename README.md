## 功能

- **展厅**：瀑布流展牌、灯箱浏览、编号展签、点赞（服务端按会话幂等）、排序（最新/最热）、筛选（馆藏精选/观众投稿）、随机抽件
- **实时**：聊天室实时推送、新批准作品实时上墙、在线人数（Presence）
- **投稿**：注册或匿名均可；浏览器端压缩 → 直传云端隔离区 → 管理员审核后公开
- **账号**：邮箱验证码注册/登录（EmailJS），可选密码（PBKDF2 加盐哈希，12 万次迭代，本机存储）
- **人机验证**：Canvas 扭曲字符 + 干扰线噪点 + 行为分析 + 一次性令牌防重放
- **每日信标**：按日期确定性生成的馆藏签文
- **管理后台 2.0**：待审/已发布管理、邮件服务配置、访客统计、操作审计、IP/邮箱封禁、用户管理

## 安全模型（2026-08-22 审计后终态）

1. **行级安全（RLS）**：所有表启用；访客只读「已批准」作品与公开聊天；管理数据（统计/日志/封禁/用户）仅管理员函数可触达。
2. **存储分区隔离**：
   - `pending/` — 投稿隔离区：匿名**只写**（≤30 次/小时），不可枚举、不可读
   - `art/` — 公开区：匿名只读；匿名**不可写**
   - 审批/下架时由管理员客户端经 Storage move API 物理搬移（`savage_admin_update` 策略放行）
3. **服务端强制校验**：
   - `art_submit`：密钥必须落在 `pending/`；时间戳必须在服务器时间 ±24h（堵住限流绕过）；保留名保护；10 次/分钟全局限流
   - `art_approve` / `art_reject`：仅 authenticated 可调用，函数内二次校验 `admin_users`；编号自 101 起（避开馆藏 001–010）
   - `chat_send`：每会话 3 条/3 秒 + 全局 15 条/3 秒 + 保留名保护
   - `art_like`：按会话幂等 + 全局 20 次/3 秒限流
4. **聊天隐私**：`chat` 表列级授权，`session_key` 对访客完全不可见（REST 与 Realtime 双通道验证通过）。
5. **不可猜测的对象密钥**：作品 ID 为 96bit 加密随机数（`crypto.getRandomValues`），待审对象无法被枚举或暴力定位。
6. **前端防线**：严格 CSP（script-src 'self' + 白名单 CDN，全部 SRI 校验）、全站 XSS 转义、无内联事件处理器。
7. **Realtime 发布**：`chat` 与 `art` 已加入 `supabase_realtime` 发布（此前缺失，实时推送实际未生效，本次修复）。

### 已知边界（设计取舍，非漏洞）

- 公共直链路由（`/object/public/...`）不做 RLS 检查：待审图片若被**精确猜中密钥**仍可读——已由 96bit 随机密钥 + 禁止枚举兜底；如需绝对保密，后续可将桶改为私有并全面启用签名 URL。
- 访客埋点 IP 来自客户端上报（GitHub Pages 无服务器），IP 封禁对刻意伪造者约束有限。
- 「观众账号」为本机存储（跨设备不同步）；唯一的服务端账号是管理员。若需真实多端账号，可迁移至 Supabase Auth。
- EmailJS public key 在前端可见（设计如此）：请在 EmailJS 控制台为该 key 配置**域名白名单**，防止额度被外部盗用。
